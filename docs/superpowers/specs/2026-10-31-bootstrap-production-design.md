# 开局产线（Bootstrap Production）设计

日期：2026-10-31 · 状态：M1（领域核心）已实现；M2、M3 待做

## 1. 目标

发射到一个新区块后，以核心为中心自动完成前期基础生产：

- 铜、铅、钛直接采到核心；
- 用蓝图模块生产石墨、硅、钢化玻璃，原料（煤、沙、铅）由矿区直接供给；
- 自动配平采集量与模块需求，自动建电厂（必要时自动找水源），自动避开敌人路线；
- 先规划终局布局，玩家确认一次，之后按核心库存**分步自动下发建造**。

非目标（本期不做）：算法生成工厂内部布局；核心中转（卸载器）供料；Erekir；单个入口汇入多条线。

## 2. 已确认的决策

| # | 决策 | 结论 |
|---|---|---|
| D1 | 供料拓扑 | **直连产线**：矿区 → 模块入口，模块产物 → 核心 |
| D2 | 交互方式 | **先规划终局，确认一次后分步自动建**，可暂停/取消 |
| D3 | 产量目标 | 以**模块**为单位：每种产物选 N 个模块（默认 1），每个模块按满速配平；铜、铅、钛作为原材料目标，默认各一条满速线到核心 |
| D4 | 工厂来源 | **只用蓝图**；规划器不生成工厂内部 |
| D5 | 开局不满足满速 | **同一蓝图分步喂满**：先建模块，原料线逐条接入；缺钛时模块内与外部线的钛带都换成普通传送带（见 4.5），之后有"升级为钛带"的步骤 |
| D6 | 矿区/模块位置 | **全自动勘探与选址**，可选框定基地范围；自动避开敌人路线与射程 |
| D7 | 电厂 | **电厂也是蓝图模块**；前期燃烧发电机（内置），有硅/石墨/水后可用涡轮发电机模块 |
| D8 | 步骤顺序 | **按回本速度贪心**，依赖约束下选"新增收益 ÷ 造价"最高的一步，每步完成后重排 |
| D9 | 架构 | **DDD**：限界上下文分包、领域层纯 Java；基地在空间上按**分区（Zone）+ 干线走廊（Corridor）**组织 |

## 3. 架构

### 3.1 分层

```
ui/      BootstrapJob（第三个标签页"开局产线"）、预览绘制、步骤清单
  │
app/     用例编排：PlanBaseUseCase（勘探→配平→布局→分步）、Director（运行期状态机）
  │      只依赖 domain 与 domain 定义的端口接口
domain/  纯 Java、零游戏依赖、可离线测试；按限界上下文分包
  ▲
infra/   游戏适配器：实现 domain 端口（地形快照、方块目录、核心库存、建造下发、蓝图读取）
```

依赖方向只能向下指向 `domain`；`infra` 实现 `domain` 中声明的端口接口（依赖倒置）。现有 `autobuild.plan`（`DrillLayoutPlanner`、`GridRouter`、`PowerNetwork`）视为**算法库**，由领域层通过防腐层适配器调用，本期不改动它们的行为，不影响现有采矿场/防御工事功能。

### 3.2 包结构

```
autobuild/bootstrap/
  domain/
    shared/      共享内核：Tile、Rect、Dir、ItemId、Rate（物品/秒）、Bom（造价清单）、
                 Reservation（格子占用登记）
    catalog/     端口 Catalog：方块尺寸、造价、配方（输入/输出/周期）、耗电/发电、传送带速率
    survey/      勘探上下文：Terrain（端口，只读地形）、OrePatch、WaterBody、
                 PathField（从核心的路程代价场）、DangerMask（敌人路线 + 射程）、SurveyService
    module/      模块上下文：Blueprint（中立表示）、BlueprintCodec（msch 解码）、ModuleSpec、
                 Inlet/Outlet、ModuleAnalyzer（端口识别 + 内部流动模拟推断物品与速率）
    production/  配平上下文：ProductionGoal、SupplyLine（物品、速率、来源、去向）、ChainSolver
    mining/      采矿上下文：MiningSite、MiningSiteSolver（适配 DrillLayoutPlanner 的防腐层）
    power/       电力上下文：PowerPlantSpec、PowerGridSolver（适配 PowerNetwork）
    layout/      基地布局上下文，聚合根 BasePlan：Zone（Mining/Industrial/Power/Water）、
                 Corridor、BasePlanner、CorridorRouter（适配 GridRouter）
    staging/     分步上下文：Step、StepGraph（依赖）、Schedule、StagePlanner（库存模拟 + 贪心）
  app/           PlanBaseUseCase、Director、DirectorEvents（StepStarted/Completed/Blocked）
  infra/         GameTerrain、GameCatalog、GameInventory、BuildDispatcher、GameBlueprints
  ui/            BootstrapJob、BootstrapOverlay
```

### 3.3 限界上下文之间的关系

```
           Catalog（端口，共享）
              │
Survey ──▶ Production ──▶ Layout ──▶ Staging
  │            ▲            │  ├─ Mining（每个矿区一次求解）
  │            │            │  ├─ Power
  └─(矿团/水/危险区)        │  └─ Corridor 路由
          Module ───────────┘
```

- **Module** 只回答"一个蓝图是什么"：占地、入口（物品、满速速率）、出口、耗电/发电、造价。
- **Production** 只做数量：给定目标与模块，求每条供给线的物品与速率、所需电厂模块数。不涉及坐标。
- **Layout** 把数量落到地图：拥有唯一的 `Reservation`，保证所有分区与走廊互不重叠。
- **Staging** 只看 `BasePlan` 的步骤图与 `Catalog` 造价，不碰坐标细节。

## 4. 领域模型

### 4.1 模块（Module）

`ModuleAnalyzer` 输入 `Blueprint`（方块名、位置、朝向、配置），输出 `ModuleSpec`：

- **入口识别**：处于蓝图边缘、外侧一格为空的
  - 朝内的传送带；
  - 物品桥 / 桥接导管（外侧不是其连接方向）。
- **出口识别**：边缘上朝外的传送带。
- **沙盒标记**：蓝图里的物品源（item-source）、液体源（liquid-source）标记入口，其配置直接给出物品；物品黑洞（item-void）标记出口。标记方块本身不建造，它所在的格就是走廊的终点格。有标记时以标记为准，不再做物品推断。
- **混合出口**：一个出口可以同时产出多种物品（如 Starter Factory 三种产物共用一条带），只要它的去向是核心。
- **物品推断**：对每个入口，在蓝图内部按游戏推送规则（复用现有流动模型的规则：传送带、桥、分类器/反向分类器、交叉器、溢流门）模拟注入，看它到达哪些工厂、被当作哪种原料消耗；液体入口同理推断为水。
- **满速速率**：先按各入口的带速算供给上限，选出使模块产能最高的物品分配；再取 min(工厂总产能, 入口供给, 出口带速) 作为模块满速。例：Silicon Smelter (8) 的 8 台冶炼厂可产 12 硅/秒，但钛带只有 10/秒，所以满速是 10 硅/秒，对应 20 沙/秒 + 10 煤/秒。
- **多解的物品分配**：入口可达的工厂常常同时消耗多种原料（硅模块三个入口都能到达既吃沙又吃煤的冶炼厂），此时枚举所有分配，取模块满速最高者；仍并列则判为无法推断。
- **电力**：耗电合计；发电模块记录发电量与燃料/水消耗。蓝图内无电力节点时记 `needsNode = true`，由布局补节点。
- 无法识别或推断矛盾（同一入口推断出两种物品）时，模块标记为不可用并给出原因。

用户提供的四份蓝图的预期分析结果（作为验收用例）：

| 蓝图 | 入口 | 出口 | 电 |
|---|---|---|---|
| Silicon Smelter (8)，15×7 | 西：煤；北 ×2：沙 | 东：硅 | 耗电，内含节点 |
| Full scale Metaglass factory，8×7 | 南 (3,0)：沙；南 (4,0)：铅 | 南 (5,0)：钢化玻璃 | 耗电，内含节点 |
| Small Graphite Factory，5×6 | 北：煤（物品桥） | 南：石墨 | 无 |
| generator1，6×6 | 南：可燃物（物品桥）；西：水（桥接导管） | — | 发电，需补节点 |
| Starter Factory，7×7 | 北，物品源标记：煤 (2,6)、沙 (4,6)、铅 (6,6) | 南 (2,0)，物品黑洞标记：石墨 + 硅 + 钢化玻璃混合 | 自带燃烧发电机与太阳能板 |

内置默认模块：硅（Silicon Smelter (8)）、涡轮电厂（generator1）、燃烧发电机电厂（新做，只用铜铅）。石墨、玻璃、Starter Factory 三份带 Steam 创意工坊标记，**不打包进发布版**，玩家从自己的游戏蓝图中选用；它们只作为本地测试用例（放在 git 忽略的目录）。种子模块默认用一台石墨压缩机的内置小模块（只用铜铅），玩家可改选 Starter Factory。

### 4.2 勘探（Survey）

- `PathField`：从核心出发的多源 Dijkstra：走一格代价 1，桥跳（跨 2..射程格，可越过任何东西）代价 2。
- `OrePatch`：同一物品、8 连通的矿格聚成矿团（墙下矿格排除，矿物判定沿用游戏规则：沙低优先级）；记录格数、外接矩形、到核心路程。
- `WaterBody`：可放机械泵的水格连通块。
- `DangerMask`：`EnemyRoutes` 计算的地面路线，加上路线两侧敌人射程（波次分析的加权射程）；空中路线按直线加射程。**任何分区与走廊都不得进入**。
- 可选的"基地范围"矩形：范围外的格子在勘探中不可用。

### 4.3 配平（Production）

输入：`ProductionGoal`（每种产物的模块与数量；铜、铅、钛各几条满速线）、`ModuleSpec`、勘探报告、当前可用传送带等级。

1. 汇总所有模块入口的需求速率；电厂模块数 = ⌈总耗电 ÷ 单模块发电⌉，其燃料需求再加入煤的需求（迭代到不动点）。
2. 每个入口生成一条 `SupplyLine`（物品、目标速率、去向 = 该入口）；铜、铅、钛生成去向 = 核心的线。钛矿需要气动矿机，它的造价含石墨，这一依赖由分步阶段处理。
3. 每条线的速率上限 = 所用传送带速率；超出时该线标记为"欠供"，列为后续升级步骤。
4. 为每条线挑选矿团：优先级 电厂线 > 模块线 > 核心线，同级按速率从大到小；每条线从最近的、还有余量的矿团取，一个矿团可分给多条同物品线。矿团产能 = 格数 × 覆盖率（默认 0.8）× 最好的可用矿机每格速率。
5. 模块某条线不够时整台模块降速，其余线按同一比例降低目标后重新分配；真正卡住的线标记为瓶颈，写进摘要。

### 4.4 布局与分区（Layout）

`BasePlan` 是聚合根，持有 `Reservation`、所有 `Zone` 与 `Corridor`。不变式：格子独占；每条走廊只运一种物品或一种液体（例外：去向是核心的混合出口）；不进入 `DangerMask`；不压其他有价值的矿格（与现有规则一致）。

| 分区 | 内容 | 求解方式 |
|---|---|---|
| **MiningZone** | 一片矿团上的矿机、内部传送带/桥、矿机电力与供水 | 矿团外接矩形（加边距）作为区域，调用 `DrillLayoutPlanner`，输出口设在面向走廊的边上 |
| **IndustrialZone（工业区）** | 若干工厂模块紧凑排列，模块间留 1 格通道；区内电网 | 在空地上枚举候选矩形，评分 = Σ（线速率 × 走廊路程）；默认一个工业区，放不下时拆成多个 |
| **PowerZone** | 电厂模块；紧邻工业区，电力节点把两者连成一张网 | 同上，附加"到工业区距离"项 |
| **WaterZone** | 水面上的机械泵 | 从电厂水入口反向在 `PathField` 上找最近的 `WaterBody` |
| **Corridor（干线走廊）** | 分区之间的传送带/桥或导管 | `GridRouter` 在整张地图上 A*；已规划格子写入 `Reservation`，后续走廊绕开 |

求解顺序：工业区与电厂选址 → 摆放模块 → 按速率从大到小逐条 `SupplyLine` 求解 MiningZone 并路由 Corridor → 产物出口到核心的 Corridor → 电网。逐条求解不是全局最优，沿用"换个方案"机制：用不同的线序和工业区候选位置跑多遍，取总分最高者。

### 4.5 分步（Staging）

**步骤**是建完即产生收入的最小单元：

- 一片矿区连同它的走廊；
- 一个工厂模块（含它到核心的出口走廊）；
- 一个电厂模块（含水区）；
- 一条线从普通带升级为钛带。

每步记录：造价 `Bom`、依赖（上游步骤、所需材料是否有产出来源）、建成后新增的产物速率。

`StagePlanner` 离线模拟核心库存随时间变化：每轮在依赖已满足、按当前收入可在有限时间内攒够材料的步骤中，选"新增收益（按产物权重）÷ 造价"最高者；输出有序 `Schedule` 与预计时间线。

**缺钛时的替换**：钛线建成之前，核心里没有钛（也没有钛的收入）时，模块内部与走廊上的钛传送带一律替换为普通传送带。用户的硅、玻璃模块里钛带只出现在入口/出口格，这些格本来就受外部线速率限制，替换不影响内部结构。核心里有了钛之后，"升级为钛带"的步骤才会变为可选。

**死锁处理**：若没有任何可行步骤，而缺的是某种只能由模块产出的材料（游戏 v160.7 实测造价：窑与气动矿机要石墨，机械泵要钢化玻璃，涡轮发电机与太阳能板要硅；石墨压缩机、硅冶炼厂、物品桥只要铜铅。典型死锁：核心无石墨时要采钛——气动矿机要石墨），插入**种子步骤**：用种子模块（默认内置的单台石墨压缩机，或玩家选的 Starter Factory），原料线直接接入，产物送回核心，产够后再继续。

**步骤内按材料逐块建造**：一步里的方块按“材料已够”的子集先下发，缺材料的方块等待。例如 Starter Factory 里的窑要石墨，会等压缩机产出石墨后再建；压缩机与硅冶炼厂先运转。

## 5. 运行期（Director）

状态机：`Idle → Waiting(step) → Building(step) → Waiting(next) … → Done`，可 `Paused`/`Cancelled`。

- 每 2 秒检查一次：下一步造价是否已被核心库存覆盖；满足则把该步的建造计划追加到玩家单位队列。
- 下发前逐个用游戏规则校验可放置；被玩家建筑占用或地形变化时，该步标为 `Blocked`，提示并提供"只重算受影响分区"。
- 检测该步所有方块建成 → `Completed` → 用实际库存与收入重排剩余步骤。
- 已完成步骤中的方块被摧毁时，重新下发缺失部分（修复），不重排。
- 玩家单位死亡/重生后重新下发当前步骤。

## 6. 界面

- 新标签页"开局产线"：每种产物的模块选择（游戏蓝图列表 + 内置默认）与数量；产物权重；可选"框定基地范围"；传送带等级。
- 预览：整套终局布局按步骤序号着色；摘要列出步骤清单（造价、预计开始时间、新增产量）、瓶颈与欠供提示、无法识别的蓝图原因。
- 确认后屏幕角落显示当前步骤、等待的材料与进度；暂停/取消按钮。
- 所有文本进中英文 bundle。

## 7. 错误处理

| 情况 | 处理 |
|---|---|
| 蓝图端口无法识别或推断矛盾 | 该模块不可选，显示原因 |
| 矿不够 | 降产并在摘要中写明瓶颈物品 |
| 工业区/电厂放不下 | 拆成多个工业区；仍不行则去掉优先级最低的模块并说明 |
| 走廊不通 | 换下一个候选矿团；全部不通则该线标记失败 |
| 找不到水源 | 电厂退回燃烧发电机模块 |
| 分步死锁 | 插入种子步骤；种子也不可行时报告缺少的材料 |
| 运行期步骤被阻挡 | `Blocked`，提示并可局部重算 |

## 8. 测试

- **离线**（扩展 `./test.sh`，编译范围加入 `bootstrap/domain/**`）：
  - `ModuleAnalyzer`：四份用户蓝图得到 4.1 表中的结果；人工构造的边界蓝图（无入口、混料入口、角落桥）。
  - `ChainSolver`：速率守恒（每个入口供给 = 需求或标记欠供）、电力覆盖、矿不够时的降产。
  - `BasePlanner`：随机地图的不变式——无重叠、每条走廊单一物品且端点正确、不进危险区、电网连通、每台矿机连到出口（复用现有 FlowCheck）。
  - `StagePlanner`：库存模拟中材料不为负、依赖不被违反、核心无石墨时插入种子步骤。
  - `Catalog` 的离线实现使用一份从游戏导出的方块数据快照（服务器命令一次性导出，存为测试数据）。
- **专用服务器实测**：在真实地图上直接放下整套 `BasePlan`，测量各产物速率与预测对比（沿用 `servertest.sh` 的做法）。
- **客户端自测**：从空基地开始运行 Director，记录每步开始/完成时间与最终产量，截图。

## 10. 风险

- **与 `RemotePorts` 重复**：走廊路由的纯算法部分与 `RemotePorts` 里的布线逻辑相近。M2 时评估把其中纯算法部分抽到 `autobuild.plan` 供两边共用。
- **流动推断的覆盖面**：玩家蓝图可能用到超出流动模型的方块（如质量驱动器、物品源）。遇到未知方块时，该入口推断失败并显示原因，不猜测。
- **分步模拟与实际偏差**：玩家同时在花材料、单位建造速度有限。Director 每步完成后按实际库存重排，时间线只作参考。
